# Python test isolation with dependency stubs and native extensions

Use when focused tests pass but full discovery fails, or when tests stub dependencies through `sys.modules`.

1. Read the repository's CI test command, then reproduce the failing execution mode. Run the affected module first and the exact single-process suite next, for example `python -m unittest discover -s tests -p 'test_*.py'`. Keep the interpreter and dependency environment constant; a passing per-module subprocess does not establish that shared interpreter state is safe.
2. Search tests for `sys.modules`, `ModuleType`, dependency stubs and setup/teardown hooks. Identify which test installs each stub and which application modules retain references to it. Inspect the actual module object before removing it; tests may deliberately create modules without `__file__`, but that heuristic is not universal proof of a stub. Prefer explicit fixture ownership where practical.
3. Preserve already-loaded real native extensions such as NumPy and OpenCV. Remove only confirmed fake dependency objects; do not broadly pop and reimport real C extensions, because initialization state and child-module caches can survive removal of the top-level entry.
4. Reload the narrow set of repository modules imported against fake dependencies after replacing those dependencies. Removing a fake dependency alone does not update application modules' cached globals. Avoid clearing every third-party module as a shortcut; retain real packages and invalidate only the affected application import graph.
5. Clear fixture bookkeeping at each setup and restore only objects actually replaced by that fixture. Do not reinstall an earlier fake native dependency during teardown after the suite has loaded the real extension. Prefer scoped patching or dependency injection for future fixtures so unrelated tests retain their original modules.
6. Give subprocess regression probes an explicit repository-root `cwd` and use `sys.executable` when they must share the current interpreter. Otherwise an import success can depend on the shell's launch directory rather than the code under test. Use subprocess isolation only where the test contract permits it; do not replace single-process discovery merely to hide contamination.
7. Complete all fixture edits before rerunning focused tests and full discovery. Inspect the resulting diff, then commit only after both modes pass. Re-run remote CI on the pushed head and distinguish test execution from dependency or interpreter setup failures.
